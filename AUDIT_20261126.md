# Аудит marketplace_agent — сбой «открыл отзыв и закрыл» (обход отзывов Ozon), коммит 4c3bc9a

Дата сверки внешней информации: 20.11.2026 (страница ai.google.dev/gemini-api/docs/deprecations открыта и сверена
построчно). Проверено: весь репозиторий (~21 тыс. строк Python в `services/bot/database/maintenance/tests`),
`pyflakes`, офлайн-набор `tests/run_offline.py` (235 тестов до правок → 241 после, все OK; DOM-тесты с реальным
Chromium в песочнице не запускались — запустите у себя), сравнение с `browser_reviews ИСХОД.py`.

## 1. Что произошло в вашем тестовом прогоне (разбор консоли)

```
Фильтр Ozon НЕ подтверждён (галочки: {'С текстом': True, 'С медиа': False, 'Только с оценкой': None})
Координаты «close»: клик (1361, 25), попытка 1/2           <- окно закрывается ДО первого отзыва!
Окно отзыва закрыто (координаты крестика)
Этап 1/5: клик по ячейке «Отзыв» (столбец 4)               <- дальше «Этап 2/5» не наступает никогда
Координаты «close»: ... (повторяется)
... Нельзя однозначно выбрать карточку отзыва; 4 неудачи подряд — обход остановлен
```

Здесь два независимых дефекта. Вместе они дают ровно то, что вы увидели (клик по тексту, отзыв открыт, ничего
не прочитано, «Ответить» не нажато, окно закрыто, и так пять раз).

### Дефект A. Фильтр «Контент» кликает НЕ по галочке, а по таблице (причина «не успел нажать С медиа»)
* `_CHECKBOX_STATE_JS` / `_CHECKBOX_CLICK_JS` искали **первый во всём документе** элемент с текстом «С медиа».
  В таблице отзывов такие бейджи есть (поэтому `_clean_review_text` их и вычищает). Состояние читалось у строки
  таблицы (`False`), а `row.click()` по родителю бейджа **открывал отзыв вместо переключения галочки**.
* Поэтому «С текстом» (первый в DOM — в панели) ставилась, а «С медиа» — нет; «Только с оценкой» = `None`.
* Открытый отзыв оставался поверх таблицы → первый же `_visit_review` видел «окно уже открыто» и жал крестик
  (первая строка `Координаты «close»` до «Этап 1/5»).
* В исходнике (`ИСХОД`) было то же самое слабое место, но там после Escape/повторных кликов шторка добивалась
  `while drawer_open: close` и обход шёл дальше, поэтому незаметно.

### Дефект B. Окно отзыва открылось, но карточка «не распознана» (причина «ничего не считал»)
* `_wait_card` ждёт либо строгий селектор `_cards()`, либо мягкую `_js_is_drawer_open` (как в ИСХОД) — вторая
  срабатывает по заголовку «Отзыв на товар» / кнопке «Ответить на отзыв», и шаг проходит.
* Дальше `_open_review_card` помечает карточку: строгий путь (`role=dialog`/портал + якорь) → нет;
  запасной `_MARK_LOOSE_JS` требовал **видимый портал или `div[role=dialog]` размером ≥100×100**. У шторки Ozon
  собственный размер у `#ui-kit-side-page-portal-container` нулевой (дети — `position: fixed`; сам код это отмечает
  в комментарии к `_overlays`), `role=dialog` нет → `RuntimeError`-ветка «Нельзя однозначно выбрать карточку».
* `_SkipReview` летит ДО чтения артикула/оценки/текста и ДО «Ответить», а `finally` закрывает окно крестиком
  (`Окно отзыва закрыто (координаты крестика)`). Отсюда «клик → закрыл» ×4 и стоп по `consecutive_fail >= 4`.
* В `ИСХОД` карточка не «маркировалась»: текст брался как `innerText` первого `div` с «Отзыв на товар», кнопки —
  глобальным поиском. Эта простота и работала.

## 2. Что исправлено (патч `marketplace_agent_fix_2026-11-26.patch`)

`services/ozon/browser_reviews.py`
1. **Единый поиск окна отзыва `_DRAWER_FN` (JS)**: якорь = видимые «Отзыв на товар» / «Ответить на отзыв» **вне
   таблицы**; карточка = внешний портал/`dialog`, а если их нет — самый верхний предок якоря, не содержащий
   `tbody`/`role=row`. Размер портала и `role=dialog` больше не требуются.
   Используется в `_MARK_LOOSE_JS`, `_CLOSE_X_JS` (крестик), JS-запасе «Ответить», новом `_review_card_open`.
2. **Фильтр «Контент» только внутри панели фильтров** (панель = предок кнопки «Применить», где есть «С текстом» и
   «С медиа»); всё, что внутри `table/tbody/tr/[role=row]`, исключено. Клик — настоящий (`locator.click()` по
   метке), JS-`click()` — только запасной. Вслепую (когда галочка не найдена) не кликаем.
3. Порядок: сначала снять «Только с оценкой», затем «С текстом», «С медиа»; до 3 кругов; результат читается из
   панели → лог ожидается: `Фильтр Ozon применён (галочки: {'С текстом': True, 'С медиа': True, 'Только с оценкой': False})`.
4. Если клик случайно открыл отзыв — `Клик по «…» открыл карточку отзыва — закрываю`, панель фильтров открывается
   заново; после «Применить» панель гарантированно закрывается (Escape ×3), случайно открытая карточка закрывается,
   затем пауза 0,5 с на перерисовку таблицы.
5. `_filters_panel_open` теперь смотрит на «Применить» вне таблицы (заголовок «Контент» может быть и в таблице).
6. **Диагностика**: при «Нельзя однозначно выбрать карточку» пишутся предки якоря, размер портала и скриншот
   `logs/review_fail_card_<время>.png` (раньше следов не оставалось — пункт 6 прошлого аудита).
7. Тесты: `tests/test_audit_20261126b.py` (3 проверки JS-контрактов + 3 DOM-проверки при наличии Chromium).
   Логику JS дополнительно прогнали в jsdom на 5 сценариях (портал нулевого размера; шторка без портала и без role;
   строка таблицы с текстом «Отзыв на товар» не считается; бейдж «С медиа» в таблице не читается как галочка;
   нет панели → `null`, клика нет).

Ожидаемый тестовый прогон теперь:
```
Фильтр Ozon применён (галочки: {'С текстом': True, 'С медиа': True, 'Только с оценкой': False})
Этап 1/5: клик по ячейке «Отзыв» (столбец 4)
Артикул: … | оценка: N★ | …   /   Оценка: N★ (цвет звёзд=…, текст=…, таблица=…)
Этап 2/5: нажимаю «Ответить на отзыв»
Этап 3/5: ответ вставлен (… зн.)
[dry_run] ответ вставлен, не отправляю — закрываю окно без сохранения
Окно отзыва закрыто (…)
```
Ограничение: живой Ozon мне недоступен. Если после патча снова «карточка не распознана» — пришлите строку
`Диагностика окна отзыва (card): {...}` и PNG из `logs/` — по ним правится один селектор.

## 3. Прочие баги и неточности (не правились, кроме отмеченных)

1. `OZON_REPLY_DRY_RUN`: `config.py` → `False`, `.env.example` → `true`. Без ключа в `.env` ответы публикуются сразу.
   Рекомендую `True` по умолчанию. (AUDIT_20261125 п.2 — не исправлено.)
2. `MIN_TARGET_DATE=13.11.2026` зашита и через `max()` перекрывает `OZON_REVIEWS_MIN_DATE`; имя функции
   `_is_date_from_nov_13_2026` — тоже зашито. `MAX_DAILY_REPLIES=50` — константа, а не настройка.
3. Мёртвый код: `REV_SKU_PT`, `REV_INPUT_PT`, `REV_SEND_PT`, `REV_CLOSE_PT`, `REV_MODAL_CLOSE_PT`, `Q_INPUT_PT`,
   `Q_CLOSE_PT` (используется только `_close_question_drawer`), `REV_STAR_PT` (читается в `_detect_rating`), `VIEWPORT 1440×900`
   при калибровке 1800×966; `calibrate_clicks.py` дублирует `calibrate_review_steps.py`.
4. `_js_is_drawer_open` даёт ложное «открыто» для ЛЮБОГО непустого `#ui-kit-side-page-portal-container`
   (в том числе панели «Фильтры», тостов). Из-за этого `_visit_review` жмёт крестик ещё до первого отзыва.
   Для проверки именно карточки используйте новую `_review_card_open`.
5. `_close_review_drawer` возвращает `True`, если `_overlays` пуст (нет `role=dialog`), хотя шторка открыта; спасает
   только последующий `_force_close_drawer`. Работает, но шумит в логах.
6. Воркер всегда `headless=True`; скриншот при сбое появился только для случая «карточка не выбрана».
7. `FALLBACK_MODELS` содержит и `gemini-3.6-flash`, и `gemini-3.5-flash`, а `gemini-3.5-flash` на стороне Google
   автоматически идёт в `gemini-3.6-flash` — одна и та же модель опрашивается дважды. `FAST_MODELS[0]` =
   `gemini-3.1-flash-lite`, а `GEMINI_FAST_MODEL` по умолчанию = `gemini-3.5-flash-lite` (разные «быстрые» модели).
8. Версии в `requirements.txt` из 2024 г.: `playwright==1.48.0`, `aiogram 3.13.1`, `aiohttp 3.10.5`,
   `pydantic 2.9.2`, `APScheduler 3.10.4`; `pyflakes` — dev-зависимость в боевом файле. Playwright 1.48 не знает
   актуальных сборок Chromium — обновите вместе с `playwright install chromium`.
9. `tests/run_offline.py` возвращает код 1 из-за «Offline isolation violations: 4» при зелёных тестах (воспроизводится
   и до правок) — CI будет красным.
10. `pyflakes`: в тестах 5 предупреждений (неиспользуемые импорты `tests.offline`, `settings`, `STATE`, переменная `page`
    в `test_audit_20261123b.py:42`); в продуктовом коде чисто.
11. В репозитории 10 файлов `AUDIT*.md` (~150 КБ), часть противоречит друг другу (см. п. 4). Оставьте один актуальный.
12. Файл `browser_reviews ИСХОД.py` (CRLF, пробел и кириллица в имени) — справочный, не импортируется; при
    `text=auto` git каждый раз видит его «изменённым» на Windows.
