### 0.2 Новые запасные пути

- **Telegram без локального прокси.** Раньше `ensure_working_telegram_route()` перебирал только прокси и падал, если прокси не запущен. Теперь маршруты — `direct` (если `ALLOW_DIRECT_CONNECTIONS=true`), затем все локальные прокси; ошибка содержит перечень испробованных маршрутов и подсказку. То же в `supervisor.notify`, который больше не может уронить супервизор.
- **Ozon cash-flow по полумесяцам.** Документация Ozon отдаёт финансовый отчёт только за 01–15 и 16–конец месяца. Запрос «последние 7 дней» теперь режется по этим границам (`_cash_flow_windows`); при недоступности одного окна остальные всё равно запрашиваются. Итоги сверочного отчёта принимаются **только при точном покрытии** запрошенного окна — иначе источником служат суточные начисления, чтобы P&L не показал суммы за лишние дни.
- **WB-тарифы не отменяют синхронизацию.** `fetch_wb_tariffs` при недоступности commission/box API возвращает пустую форму `{"subjects": {}, "warehouses": {}}` (и не кэширует её), а не роняет `fetch_stocks_and_prices`. Разбор тарифов, списаний рекламы и состава кампаний переведён на необязательные поля: битые строки пропускаются, а не дают `KeyError`.
- **Playwright — необязательный ярус.** Модуль отзывов импортируется без Playwright (заглушки `PWError`/`PWTimeout`); функции возвращают понятное сообщение с командой установки вместо `ImportError`, из-за которого раньше не стартовал весь бот.
- **HTML-отчёт Совета ИИ.** При ошибке записи на диск возвращается `None`, и воркер не пытается отправить несуществующий документ: приходит краткий итог и предупреждение.
- **Ozon переименовал `accruals.type_id` → `accruals.accrual_id`** (уведомление 14.07.2026). Парсер читает оба ключа; контейнер начисления больше не принимается за услугу, поэтому сумма продажи не задваивается. Возврат (отрицательная `seller_price`) возвращает и комиссию — расход не завышается. Для начислений без `operation_id` идентификатор заказа собирается из `posting_number`/дня.
- **WB: три уровня финансов.** Детализация `finance-api` (недельная → дневная) → итоги закрытых отчётов `/sales-reports/list` → прежний `GET /api/v5/supplier/reportDetailByPeriod`. Ошибка первых двух источников больше не обрывает отчёт: причина попадает в `source` (например, `HTTP 404`), а суммы берутся из следующего уровня.
- **Длинные HTML-сообщения.** Лимит Telegram считается по «сырой» длине (теги и `&amp;` тоже занимают место). Прежний расчёт по видимому тексту давал куски до 6135 единиц UTF-16; теперь каждый кусок ≤ 3900 с сохранением парности тегов и сущностей.
- **Ошибка любого обработчика бота.** Глобальный `@dp.errors()` отвечает администратору типом и текстом ошибки и возвращает `True`: polling продолжается, кнопка не «молчит». Недоставка уведомления не влияет на работу.
- **Сбой БД после подтверждения цены.** Если `finish_price_action` упал, администратор всё равно получает результат операции и предупреждение «статус не сохранён, сверьте цену в кабинете».
- **Супервизор.** `start_worker` при занятом порте или битом `.env` больше не завершает супервизор: включается экспоненциальная пауза 5–300 с. Ошибки обслуживания и сигнала перезапуска изолированы.
- **Настройки и скрытый запуск.** `runtime_bootstrap.py` перенаправляет `stdout/stderr` и `excepthook` в `logs\worker.log` / `logs\supervisor.log` **до** импорта `config`, поэтому traceback при битом `.env` больше не теряется. Ошибка обязательных ключей `.env` переведена в человекочитаемое сообщение. Некорректный `TIMEZONE` или отсутствие `tzdata` не роняют планировщик (fallback `Europe/Moscow` → UTC+3).

## 4. Инспектор и ремонт

- `maintenance/ai_inspector.py` · `inspect_project`, `inspect_source`, `recent_log_issues`: AST и компиляция исходников, Pyflakes для имён, `spec_from_file_location` и разрешение импортов без запуска приложения. Проверяются локальные экспорты и определимые атрибуты модулей. Остальные ошибки атрибутов выявляются по traceback, а не угадываются по имени переменной. В рабочем режиме читаются ограниченные хвосты свежих `*.log` (24 часа, 128 КиБ, сохранение позиции); повторяющиеся HTTP-ошибки выводятся диагностикой, а не становятся поводом переписать код.
- `maintenance/self_healer.py` · `run_full_self_check_and_heal`; `maintenance/supervisor.py` · `repair_file`, `_validate`; `bot/handlers/patch_fsm.py` · `process_patch_instruction`: у `/patch`, ручной и ночной проверки один механизм. В Gemini передаются **полный разрешённый `.py` и описание сбоя**, а не исходные логи. Модель — строка; `maxOutputTokens=16384`. Незаконченный ответ, потеря определений, изменение оригинала во время генерации, синтаксическая ошибка или неподходящий путь блокируют запись.
- Перед заменой создаётся `backups/<filename>_<timestamp>.bak`. Применяются AST, `py_compile` и атомарная запись. В режиме супервизора `WorkerSupervisor.verify_patch` требует свежий `running` heartbeat **нового PID**; при провале проверок после установки оригинал восстанавливается, результат направляется администратору. В автономном режиме без супервизора проверка файла не равнозначна проверке перезапуска процесса. Эти механизмы проверялись на временных исходниках, синтетических логах и временных копиях.

## 5. Воркер, сеть и управленческие отчёты

- `worker.py` · `main`, `_run_polling_with_conflict_guard`, `configure_scheduler`: сначала эксклюзивная блокировка, затем бот и polling. 409 отслеживается в middleware `GetUpdates` — внешний `try/except` не видел бы повторов внутри aiogram. Код выхода 75 останавливает перезапуски в `supervisor.py::WorkerSupervisor.run_forever`. Обработчики отзывов и вопросов планируются **при запуске и каждые 30 минут**; циклы Playwright не накладываются. При завершении освобождаются сессия бота, БД и сокет. Windows-лаунчеры привязаны к каталогу скрипта, а не к `C:\marketplace_agent`.
- `config.py`, `services/common/routes.py` · `request_routes`, `request_with_failover`, `mark_route_failed`; `gemini.py` · `generate`: каждый запрос перебирает **все** доступные маршруты — прямой адрес площадки/Google первым, затем локальные HTTP-прокси. Упавший маршрут уходит в карантин на `ROUTE_COOLDOWN_SECONDS`, следующий берёт работу; в кэше хранится отпечаток рабочего маршрута, не реквизиты, а нелокальные прокси отклоняются. Проверены перебор маршрутов при `ServerDisconnectedError`, закрытие `aiohttp`-сессий при таймауте и отмене, отказ при отсутствии маршрута, фильтрация моделей и незавершённых ответов. `maintenance/api_inspector.py` отдельно маркирует срезы маркетплейсов с учётом кэша и показывает состояние маршрутов.
- `database/models.py`, `database/crud.py`, `products_catalog.py`: стоимость учитывается по `(marketplace, sku)`. Не используются Ozon SKU как WB nmID или Ozon product_id. Для новых карточек БД убраны выдуманные исходные значения логистики и скорости продаж. Миграции или пересчёт существующей базы не выполнялись.
- `services/common/orders_report.py` · `sync_and_generate_orders_report`; `financial_pnl.py` · `generate_weekly_top_and_unprofitable_report`; `unit_economics.py` · `calculate_floor_price`: различаются фактические списания и расчётные ставки; возврат комиссии может быть приходом, а эквайринг не списывается дважды. Распределение доставки учитывает несколько единиц в отправлении. Неизвестная дата заказа не заменяется сегодняшней; отсутствие разбивки цены, доставки или себестоимости обозначается в отчётах. **Контрольный пример**, не результат магазина: доставка 38,87 ₽/заказ; эквайринг Ozon 44,85 ₽ один раз; прибыль Ozon 939,35 ₽ + WB 184,50 ₽ = 1 123,85 ₽.
- `services/common/ai_advisory_board.py` · `generate_monday_ai_board_report`; `services/competitors/deep_parser.py` · `run_full_competitor_deep_audit`: советник использует финансовый срез, а не заранее заданную стоимость маршрута. Публичная цена конкурента не доказывает его себестоимость, СПП и прибыль. Сценарный калькулятор требует явных исходных сумм вместо подстановки 39/55 ₽. При недоступной витрине отчёт показывает отсутствие данных.
- `bot/keyboards.py`, `bot/handlers/{callbacks,costs_fsm,logistics_fsm,questions_fsm,reviews_fsm,patch_fsm}.py`: проверены регистрация маршрутов, доступ администратора, отмена/возврат в меню, ввод стоимости и количества, экранирование Telegram HTML. Длинные сообщения сохраняют пары тегов, сущности и границы символов при разбиении.

## 6. ТОП-5 и разбор витрин конкурентов (18.11.2026)

- `services/common/financial_pnl.py` · `generate_weekly_top_and_unprofitable_report`, `_fetch_sku_sales`, `_build_stats_from_sku_sales`. **Найденная причина пустого отчёта:** рейтинг строился только по детализации начислений Ozon и закрытых отчётов WB, а они формируются с задержкой в несколько дней. За свежую неделю детализация пуста, поэтому кнопка «🏆 ТОП-5 и Убыточные» отвечала «заказов не найдено», хотя продажи были. Добавлен второй ярус источников per-SKU:
  - Ozon — `fetch_sales_by_sku`: `/v1/analytics/data` по измерению `sku` (наборы метрик `ordered_units+revenue` → `ordered_units`). Если выручка недоступна, количество берётся фактом, а цена — текущая из ЛК; в отчёте это прямо подписано как оценка.
  - WB — `fetch_sales_by_sku`: детализация отчёта реализации → «Лента заказов» `/api/analytics/v1/order-feed`.
  - Комиссии и логистика в резервном ярусе берутся из сводного отчёта за период (удельные ставки), тариф WB — `boxDeliveryBase` по складам. Себестоимость — только подтверждённая: артикул без неё даёт «н/д» и попадает в отдельный список, а не в прибыль.
  - Отчёт честно помечает источник: «Рейтинг построен по резервному источнику (начисления/детализация ещё не сформированы)».
- `services/wb/statistics_api.py` · `fetch_sales_by_sku`, `services/ozon/seller_api.py` · `fetch_sales_by_sku`: результат кэшируется на диск (15/30 мин), чтобы повторное нажатие кнопки не дёргало API и не ловило 429.
- `services/competitors/browser_listings.py` — новый браузерный ярус разбора витрин на базе открытых парсеров WB/Ozon:
  - WB: реальный Chromium решает челлендж JVO1, затем перехватывается **собственный** ответ сайта на `search.wb.ru/.../v18/search`. Воспроизведение `x_wbaas_token` из httpx не используется: токен привязан к браузеру, который решил челлендж (иначе 498). Резерв — разбор DOM-карточек.
  - Ozon: один Chromium открывает главную `ozon.ru` и остаётся открытым; `fetch` выполняется из контекста этой страницы, ответ разбирается как `widgetStates` рекурсивным обходом (пути к товарным массивам у Ozon меняются). Резерв — DOM-карточки по ссылкам `/product/...-<sku>/`.
  - Изображения/шрифты/стили **не** блокируются: скрипты антибота грузятся через них.
  - Бюджет времени (`LISTINGS_BROWSER_BUDGET_SEC`, 90 с) и кэш на 10 минут: браузер не может подвесить отчёт. Если Playwright не установлен, возвращается понятное сообщение, а не зависание.
- `services/competitors/deep_parser.py` · `_parse_wb_competitors_with_status`, `_parse_ozon_competitors_with_status`: ярусы выстроены как HTTP → браузер → явный статус. Итоговый текст различает «витрина закрыта антиботом» и «браузерный разбор недоступен», вместо общего молчания.
- `worker.py` · `_guarded_job`, `configure_scheduler`: **все десять** фоновых задач обёрнуты в единый сторож. Раньше необработанное исключение в задаче уходило только в лог APScheduler, которого скрытый запуск через `pythonw.exe` не видит, — отчёт «не приходил» без объяснения. Теперь любой сбой приходит админу в Telegram, а планировщик и остальные задачи продолжают работать.
- `worker.py` · `cmd_manual_audit`, `btn_sync_mp`: у кнопок появились статус-сообщение и разбор ошибки — они были единственными обработчиками без обработки исключений.
- `services/common/ai_advisory_board.py` · `generate_monday_ai_board_report`: падение одного источника (финансы, ТОП-5, остатки, БД) больше не обнуляет весь разбор Совета; запись HTML-файла защищена от ошибок диска.
- `services/common/financial_pnl.py` · `generate_monthly_pnl_report`, `maintenance/self_healer.py` · `run_full_self_check_and_heal`: отчёт по кнопке и ночная самопроверка возвращают понятный текст вместо трейсбека.
- Удалён мусор в корне репозитория (файлы `0`, `60`, `None`, `int`, `str`, `{r.status}`, `1.12.0`, `requirements.txt.txt`, пустой документ в `bot/`), оставшийся от ошибочных перенаправлений вывода.

## Как воспроизвести и принять изменения

1. В отдельной среде Python 3.11 установить `python -m pip install -r requirements.txt`. Для DOM-тестов нужен Chromium для Playwright (`python -m playwright install chromium` либо `CHROMIUM_EXECUTABLE_PATH` к совместимому браузеру).
2. Из корня: **`python -m tests.run_offline`**. Перед импортом настроек подставляются тестовые значения, SQLite `:memory:` и временные каталоги. Runner запрещает Python-доступ к защищённым путям проекта и внешним сокетам. Во время контрольного прогона: `Offline isolation violations: 0`.
3. **Что остаётся оператору:** на стенде с действующей авторизацией кабинета начать с `OZON_REPLY_DRY_RUN=true`, сверить селекторы шторки и даты. До включения публикации проверить один отзыв вручную. Для цен сверить одну согласованную позицию: Ozon — результат по товару и витрину с учётом акции; WB — ID загрузки, применение/карантин и порог акции отдельно. Для финансов сверить тот же закрытый период и единицы измерения с отчётом ЛК. Боевые ключи, внешние права, текущая разметка Ozon и запуск под Windows в этом аудите не проверялись.
