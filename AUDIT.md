# YaSoKo · аудит marketplace_agent

**18 ноября 2026 · Python 3.11 · база сравнения `19e3afd`.** Исправлены пять связанных контуров — от кнопки в Telegram до запроса изменения цены и от обхода отзывов до проверки готовности перезапущенного воркера.

**Результат проверки:** 63 теста в одном офлайн-прогоне, 0 ошибок, 0 пропусков. В их числе — реальный диспетчер aiogram и четыре сценария в headless Chromium. Проверены компиляция 51 Python-файла, Pyflakes, разрешение импортов, совместимость зависимостей и `git diff --check`. Это проверка кода и контрактов, **не** свидетельство изменения цены, публикации отзыва или величины расходов реального магазина. Рабочие `.env`, `logs/`, `backups/` и файлы БД в проверке не использовались.

## 1. Подтверждение и запись цены

| Где | Что исправлено |
|---|---|
| `services/common/price_auditor.py` · `run_daily_price_audit`, `evaluate_ozon_dual_scenarios` | Карточка Ozon содержит три действия: **299 ₽ и прибыль**, **расчётная цена >300 ₽ и прибыль при 52%**, отклонение. Расчёт учитывает себестоимость, первую милю, доставку из отчёта, ПВЗ для FBS, рекламу, УСН и эквайринг. Средние расходы обозначены как оценка. При недостаточных данных для рекомендации кнопок нет. |
| `database/crud.py` · `create_pending_action[s]`, `claim_price_action`, `finish_price_action`, `recover_interrupted_actions` | Обе альтернативы одного предложения сохраняются одной транзакцией **до** отправки клавиатуры. В `callback_data` передаётся первичный ключ. Первое нажатие атомарно резервирует действие и блокирует альтернативу; поздний клик не приводит к повторному POST. Неоднозначный результат после отправки или прерванная обработка → `unknown`, требуется ручная сверка. |
| `bot/handlers/callbacks.py` · `cb_approve_action`, `cb_reject_action`, `_ozon_result`; `services/ozon/seller_api.py` · `update_price` | У Ozon `POST /v1/product/import/prices` получает числовой `product_id`, строковые `offer_id` и `price`, а также `auto_action_enabled: "UNKNOWN"`. Успех — только один подходящий элемент с `updated is True` без ошибок. Отказ отображается в Telegram; сам HTTP 200 недостаточен. |
| `services/wb/statistics_api.py` · `update_price_and_min_price` | Принимается положительный `int` nmID, не SKU и не ID действия. Скидка читается для **того же nmID**. В `https://discounts-prices-api.wildberries.ru/api/v2/upload/task` передаются база `round(target / (1 - discount / 100))` и текущая скидка. `errorText` доходит до администратора. При наличии ID задачи статус — `submitted`, а не «цена установлена». **Минимум `int(round(target * 0.92))` — рекомендация:** в контракте загрузки нет поля для установки порога акции. |

**Сквозная проверка:** `tests/test_market_contracts.py::ApprovalChain` получает `callback_data` из реально построенных клавиатур, подаёт `Update` в `worker.dp.feed_update`, проверяет вызов адаптера, тело запроса, текст ошибки и состояние SQLAlchemy. Замещён сетевой транспорт, а не обработчик нажатия.

## 2. Автоответы Ozon

- `services/ozon/browser_reviews.py` · `auto_reply_unanswered_reviews`, `_scan_reviews`, `_reset_review_filters`: обходится список «Все отзывы», а если его нет — «Просмотренные» и «Новые». Важен ответ продавца/бренда в карточке, а не признак просмотра. Снимается ограничение «только текст/медиа»; есть обработка пагинации и лимитов.
- `_item_date`, `_is_date_from_nov_13_2026`: используется дата публикации в строке или шторке. **13.11.2026 включено; более раннюю и неподтверждённую дату не обрабатываем.** Дата в тексте покупателя не заменяет дату публикации.
- `services/common/buyer_questions.py` · `generate_review_reply`: при сбое генерации — до трёх попыток, а не публикация сообщения об ошибке. `_submit_review_reply` отправляет ответ один раз и ждёт признака публикации в той же открытой карточке. Одного исчезновения кнопки при открытии редактора либо очистки поля недостаточно. `_save_tracker` атомарно обновляет `replies_tracker.json` только после подтверждения отзыва; при неопределённом результате следующая проверка заново проверяет карточку. Предпросмотр не помечает отзыв отвеченным.
- `auto_reply_unanswered_questions`: сохранены калиброванные клики, поле ввода и кнопка отправки; добавлен тот же барьер даты. Тест Chromium воспроизводит старый, недатированный и допустимый вопрос, проверяя, какой ответ дошёл до кнопки отправки.

## 3. API, остатки, реклама и финансы

| Контур и точки входа | Исправление и предел интерпретации |
|---|---|
| `services/common/market_api.py` · `request_json`, `read_versions`; `storage.py` · `DiskCache` | Все HTTP-запросы к маркетплейсам идут напрямую (`trust_env=False`). Для чтения при 400/404/410/429 можно перейти на другую версию. Учитывается `Retry-After`; длинное требование паузы не обходится. Ответы кэшируются на диске по аккаунту и запросу; незаконченная страница не считается полным результатом. Для записи автоматических повторов нет. |
| `services/ozon/seller_api.py` · `fetch_stocks_and_prices` / `_load_inventory` | Цены и акции `/v5` → `/v4/product/info/prices`, остатки `/v4` → `/v3/product/info/stocks`; учитываются разные курсоры. Разделены FBO/FBS, ставки комиссий, `marketing_actions` и `fbs_first_mile`. Фактические Ozon SKU не подменяют `product_id` для записи цены. |
| `services/ozon/seller_api.py` · `fetch_real_finance_breakdown`; `services/ozon/finance.py` · `book_transaction`, `book_statement`, `complete_statement` | Транзакции `/v3/finance/transaction/list` разбиваются по месяцам и страницам. Отчёт `/v1/finance/cash-flow-statement/list` запрашивается с `with_details=true`. Два источника **не складываются**: детализация принимается при полном покрытии интервала и сверке продаж/выплаты; иначе источником служат транзакции, причина указывается. Для многопозиционного отправления не выдумывается цена отдельного SKU. Доставка на заказ — сумма услуг доставки / число уникальных отправлений, не константа 39 ₽. |
| `services/ozon/seller_api.py` · `fetch_active_ad_campaigns`; `services/common/ad_recommendations.py` · `analyze_ozon_campaigns` | Сопоставляются состав РК Performance API, её расход и атрибутированная выручка, Ozon SKU и биллинговые списания Seller API. ДРР магазина не присваивается каждой кампании. Ставка CPO не выдаётся за фактический ДРР. Неатрибутированный платный трафик или неизвестный состав не обозначаются как органика. Пример **4 товара / 6,3% и 2 товара / 15,4%** воспроизводится на входных данных теста, а не зашит в рабочий код. |
| `services/wb/statistics_api.py` · `_load_inventory`, `_fetch_fbo`, `fetch_wb_tariffs` | Карточки `content/v2/get/cards/list` связываются с размерами/баркодами → `/api/v3/warehouses` → `/api/v3/stocks/{wh_id}`. Отдельно читаются `/api/v1/supplier/stocks` либо отчёт остатков Analytics. Дедупликация складских позиций и nmID устраняет повторное суммирование и дубли карточек. Комиссия — по предмету; тариф коробки — оценка по складам, **не** фактический расход заказа. |
| Там же · `fetch_real_finance_breakdown`, `_finance_rows`, `fetch_active_ad_campaigns` | `reportDetailByPeriod` v5 → v3 → v1 с курсором `rrdid`; учитываются продажи, возвраты, комиссии и эквайринг. `acquiring_bank` не сумма; фактический ноль отличается от отсутствующего `acquiring_fee`, расчёт 1,5% помечается. Реклама: `promotion/count` → `promotion/adverts` (с резервным методом детализации) → `upd`, связь по ID, сохраняются списания завершённых РК. |

## 4. Инспектор и ремонт

- `maintenance/ai_inspector.py` · `inspect_project`, `inspect_source`, `recent_log_issues`: AST и компиляция исходников, Pyflakes для имён, `spec_from_file_location` и разрешение импортов без запуска приложения. Проверяются локальные экспорты и определимые атрибуты модулей. Остальные ошибки атрибутов выявляются по traceback, а не угадываются по имени переменной. В рабочем режиме читаются ограниченные хвосты свежих `*.log` (24 часа, 128 КиБ, сохранение позиции); повторяющиеся HTTP-ошибки выводятся диагностикой, а не становятся поводом переписать код.
- `maintenance/self_healer.py` · `run_full_self_check_and_heal`; `maintenance/supervisor.py` · `repair_file`, `_validate`; `bot/handlers/patch_fsm.py` · `process_patch_instruction`: у `/patch`, ручной и ночной проверки один механизм. В Gemini передаются **полный разрешённый `.py` и описание сбоя**, а не исходные логи. Модель — строка; `maxOutputTokens=16384`. Незаконченный ответ, потеря определений, изменение оригинала во время генерации, синтаксическая ошибка или неподходящий путь блокируют запись.
- Перед заменой создаётся `backups/<filename>_<timestamp>.bak`. Применяются AST, `py_compile` и атомарная запись. В режиме супервизора `WorkerSupervisor.verify_patch` требует свежий `running` heartbeat **нового PID**; при провале проверок после установки оригинал восстанавливается, результат направляется администратору. В автономном режиме без супервизора проверка файла не равнозначна проверке перезапуска процесса. Эти механизмы проверялись на временных исходниках, синтетических логах и временных копиях.

## 5. Воркер, сеть и управленческие отчёты

- `worker.py` · `main`, `_run_polling_with_conflict_guard`, `configure_scheduler`: сначала эксклюзивная блокировка, затем бот и polling. 409 отслеживается в middleware `GetUpdates` — внешний `try/except` не видел бы повторов внутри aiogram. Код выхода 75 останавливает перезапуски в `supervisor.py::WorkerSupervisor.run_forever`. Обработчики отзывов и вопросов планируются **при запуске и каждые 30 минут**; циклы Playwright не накладываются. При завершении освобождаются сессия бота, БД и сокет. Windows-лаунчеры привязаны к каталогу скрипта, а не к `C:\marketplace_agent`.
- `config.py`, `services/common/routes.py` · `proxy_routes`, `remember_route`; `gemini.py` · `generate`: Telegram и Gemini используют только настроенные локальные HTTP-прокси, в кэше — отпечаток рабочего маршрута, не реквизиты. Проверены закрытие `aiohttp`-сессий при таймауте и отмене, отказ при отсутствии маршрута, фильтрация моделей и незавершённых ответов. `maintenance/api_inspector.py` отдельно маркирует срезы маркетплейсов с учётом кэша.
- `database/models.py`, `database/crud.py`, `products_catalog.py`: стоимость учитывается по `(marketplace, sku)`. Не используются Ozon SKU как WB nmID или Ozon product_id. Для новых карточек БД убраны выдуманные исходные значения логистики и скорости продаж. Миграции или пересчёт существующей базы не выполнялись.
- `services/common/orders_report.py` · `sync_and_generate_orders_report`; `financial_pnl.py` · `generate_weekly_top_and_unprofitable_report`; `unit_economics.py` · `calculate_floor_price`: различаются фактические списания и расчётные ставки; возврат комиссии может быть приходом, а эквайринг не списывается дважды. Распределение доставки учитывает несколько единиц в отправлении. Неизвестная дата заказа не заменяется сегодняшней; отсутствие разбивки цены, доставки или себестоимости обозначается в отчётах. **Контрольный пример**, не результат магазина: доставка 38,87 ₽/заказ; эквайринг Ozon 44,85 ₽ один раз; прибыль Ozon 939,35 ₽ + WB 184,50 ₽ = 1 123,85 ₽.
- `services/common/ai_advisory_board.py` · `generate_monday_ai_board_report`; `services/competitors/deep_parser.py` · `run_full_competitor_deep_audit`: советник использует финансовый срез, а не заранее заданную стоимость маршрута. Публичная цена конкурента не доказывает его себестоимость, СПП и прибыль. Сценарный калькулятор требует явных исходных сумм вместо подстановки 39/55 ₽. При недоступной витрине отчёт показывает отсутствие данных.
- `bot/keyboards.py`, `bot/handlers/{callbacks,costs_fsm,logistics_fsm,questions_fsm,reviews_fsm,patch_fsm}.py`: проверены регистрация маршрутов, доступ администратора, отмена/возврат в меню, ввод стоимости и количества, экранирование Telegram HTML. Длинные сообщения сохраняют пары тегов, сущности и границы символов при разбиении.

## Как воспроизвести и принять изменения

1. В отдельной среде Python 3.11 установить `python -m pip install -r requirements.txt`. Для DOM-тестов нужен Chromium для Playwright (`python -m playwright install chromium` либо `CHROMIUM_EXECUTABLE_PATH` к совместимому браузеру).
2. Из корня: **`python -m tests.run_offline`**. Перед импортом настроек подставляются тестовые значения, SQLite `:memory:` и временные каталоги. Runner запрещает Python-доступ к защищённым путям проекта и внешним сокетам. Во время контрольного прогона: `Offline isolation violations: 0`.
3. **Что остаётся оператору:** на стенде с действующей авторизацией кабинета начать с `OZON_REPLY_DRY_RUN=true`, сверить селекторы шторки и даты. До включения публикации проверить один отзыв вручную. Для цен сверить одну согласованную позицию: Ozon — результат по товару и витрину с учётом акции; WB — ID загрузки, применение/карантин и порог акции отдельно. Для финансов сверить тот же закрытый период и единицы измерения с отчётом ЛК. Боевые ключи, внешние права, текущая разметка Ozon и запуск под Windows в этом аудите не проверялись.
